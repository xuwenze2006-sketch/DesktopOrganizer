# DesktopOrganizer v1.12.5 第四步修复报告

## 目标

解决旧版本只使用 `SystemParameters.WorkArea`、窗口只覆盖主显示器、不同显示器任务栏/空洞区域不可识别，以及显示器插拔或 DPI 改变后布局坐标失效的问题。

## 根因

1. 主窗口边界固定为主屏 `WorkArea`，副屏不在 WPF 客户区内。
2. 所有边界判断都把桌面当成从 `(0,0)` 开始的单一矩形。
3. 没有保存显示器拓扑，运行中或离线改变显示器排列后无法判断坐标属于哪块屏幕。
4. 虽已声明 Per-Monitor V2 manifest，但没有处理 `WM_DPICHANGED`，也没有把 Win32 物理显示器边界转换为窗口 DIP。
5. 智能布局、自动分类和恢复按钮均可能落入任务栏或显示器之间不存在的区域。

## 实现

### 1. 完整虚拟桌面宿主

- 新增 `NativeMethods.Display.cs`。
- 使用 `EnumDisplayMonitors` 和 `GetMonitorInfo` 获取每块显示器的 `rcMonitor`、`rcWork`、设备名和主屏标记。
- 主窗口句柄建立后，使用物理像素范围覆盖所有显示器，包括位于主屏左侧/上方的负坐标区域。
- 保留原 Progman 正上方 Z 序、透明窗口和不激活行为。
- 显示器几何不再依赖 Progman 附着是否成功；首次 Shell 尚未就绪时也会先建立完整坐标，再加载布局。

### 2. 统一客户区坐标

- 新增 `DesktopGeometry.cs` 与 `MainWindow.DesktopGeometry.cs`。
- 通过 WPF `PointFromScreen` 把每块显示器的物理像素边界转换为主窗口客户区 DIP。
- 坐标统一归一化到虚拟桌面左上角 `(0,0)`，避免负屏幕原点和 DPI 舍入干扰布局文件。
- 记录每块显示器的可用工作区，而不是只记录整个虚拟桌面的包围矩形。

### 3. Version 13 布局迁移

布局新增 `DesktopTopology`：

- 显示器设备名；
- 显示器边界与工作区；
- 主屏标记；
- X/Y DPI。

Version 12 及更早布局原本相对“主屏工作区左上角”，升级时会增加主屏工作区在新虚拟桌面中的偏移，因此主屏上的相对位置不变。

Version 13 在显示器拓扑改变时：

- 优先按设备名匹配同一显示器；
- 以项目在旧工作区中的相对比例映射到新工作区；
- 显示器消失时保守迁移到当前主屏；
- 分组尺寸保持不变并在新工作区内重新约束；
- 更新拓扑快照并原子保存。

### 4. 可用区域约束

以下对象均改为按单块显示器 `WorkArea` 约束：

- 自由图标；
- 分组拖动和缩放；
- 网格对齐及挤压排列；
- 新项目默认位置；
- 自动分类分组；
- 智能布局；
- 总控制面板；
- 隐藏面板后的恢复按钮。

网格候选会排除任务栏区域和不同尺寸/错位显示器之间的空洞。

### 5. 运行时显示变化

窗口现在同时处理：

- `WM_DISPLAYCHANGE`；
- `WM_SETTINGCHANGE`；
- `WM_DPICHANGED`。

显示配置变化发生在拖动过程中时，先取消当前交互并恢复预览快照，再重建宿主边界和迁移布局，避免半提交状态。

## 已知边界

WPF 单个顶级 HWND 同一时刻采用一个客户区缩放变换。v1.12.5 已正确映射各显示器物理边界、工作区、鼠标命中和持久化坐标，但图标视觉大小在不同缩放屏幕上保持一致。若未来要求每块屏幕上的图标按各自 DPI 独立改变视觉尺寸，需要进一步改为“每显示器一个 WPF 宿主窗口、共享布局模型”的架构。
